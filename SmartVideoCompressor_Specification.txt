================================================================================
스마트 동영상 압축기 (Smart Video Compressor) - 프로그램 기능 명세 및 개발 계획서
================================================================================
최종 업데이트 일자: 2026-07-28 (v4.67g 기준)

본 문서는 '스마트 동영상 압축기'의 전체 기능과 특징을 섹션별로 체계화한 명세서입니다.
이후 앱에 새로운 기능이 추가되거나 알고리즘이 변경될 때마다 본 문서를 지속적으로 갱신하여
최종 기능의 상태와 아키텍처, 핵심 알고리즘, 주요 오류 해결 이력을 정확히 기록하고 유지보수성을 극대화합니다.

--------------------------------------------------------------------------------
1. 메인 레이아웃 구성 (Tkinter 기반 Native UI)
   - 최상단 [가속 장치 / 코덱 / 포맷] 콤보박스 배치를 통해 가장 중요한 인코딩 뼈대를 직관적으로 선택 가능.
   - 중간 [해상도 / 프레임 / 오디오 / 회전 / 자막] 등의 세부 영상/음성 제어 패널 구성.
   - 중앙 [전체 파일에 자동 화질 적용]: 3가지 핵심 옵션(동일 용량, 동일 화질, 절약 추천) 제공. 
     * [v4.65y] 미리보기 버튼 및 메뉴 텍스트를 `🎞️ 샘플링하여 미리보기` 로 완전히 통일하고, 팝업 창 크기를 가로 1100px, 세로 720px 이내로 제한.
     * [v4.67f] [폴더 추가 하위 옵션 / 경로 이탈 방지 / 영상 누락 감지 검증 엔진]:
       (1) [폴더 추가 탐색 범위 선택 팝업]: `add_folder` 실행 시 "선택한 폴더만 탐색 (하위 제외)" vs "하위 폴더 포함 전체 탐색"을 사용자가 직접 선택 가능.
       (2) [저장 위치 절대 경로 정규화]: 네트워크 드라이브 및 루트 드라이브 경로 `src_root` 유실 방지 및 '원본 폴더에 저장' 모드 시 개별 파일 절대 경로 부모 디렉터리 100% 보장 저장.
       (3) [비디오 스트림 유실 자동 검증 엔진 (`validate_encoded_video_stream`)]: 변환 후 `ffprobe`로 비디오 트랙 유무 필수 검증. 원본 영상이 있었으나 출력물에 영상 트랙이 누락된 경우 즉시 결함 파일 삭제 및 에러 처리.
     * [v4.67g] [원본 파일 안전 보호 & 순번 자동 부여 일괄 저장 메커니즘]:
       (1) '원본 폴더에 저장' + '기존 파일명 유지하기' 모드 선택 시 원본 파일과의 경로 충돌을 자동 감지.
       (2) 원본 파일이 덮어씌워지거나 오염되지 않도록 출력 파일명 뒤에 ` (1)`, ` (2)`... 형태의 고유 순번 접미사를 자동 부여하여 100% 안전 보장.
   - 중앙 [화질(CRF) 제어 슬라이더 및 입력창]: 초보자를 위한 슬라이더 바와 전문가를 위한 직접 수치 입력 연동.
     * [v4.65y] 상단 및 개별 항목 셀 클릭 드롭다운 메뉴에 `-3`부터 `+3`까지의 화질 오프셋 옵션 전면 복원 (`추천_화질(27) -1` 포맷 표시).
   - 하단 [파일 대기열(Treeview List)]: 다중 파일 상태를 한눈에 볼 수 있는 메인 작업 영역 제공.
     * [v4.65w] 목표 화질 셀의 표시 방식을 `추천_용량(xx)`, `추천_화질(xx)`, `추천_절약(xx)`, `정밀추천_화질(xx)` 등으로 더욱 세분화하여 시인성 극대화.

[2. 핵심 인코딩 알고리즘 및 화질 제어 (Core Encoding & Quality Algorithm)]
--------------------------------------------------------------------------------
1. 코덱별 화질 및 용량 산출 알고리즘 (CRF Estimation Algorithm)
   - 화질 기준(자동 추천): 원본 해상도, 프레임, 코덱 등을 분석(b_eq 산출)하여 
     최적의 CRF 앵커(Anchor) 값을 자동으로 계산하는 자체 알고리즘 탑재.
   - [UI 및 로직 분리 / v4.65u]: 사용자가 대기열의 항목을 마우스로 클릭할 때마다 전체 파일의 '자동 화질' 적용 값이 
     해당 항목의 슬라이더 값에 맞춰 일괄 변동해버리는 치명적 버그가 있었습니다.
     -> 해결책: '전체 파일에 자동 화질 적용' 기능을 도입, 옵션을 3가지(동일 용량, 동일 화질, 절약 추천)로 
        간소화하고 각 파일이 고정된 '자동 계산 모드'를 개별적으로 부여받도록 아키텍처를 전면 분리했습니다. 
        샘플링 체크박스를 통해 필요 시 멀티스레드 정밀 모드(VMAF/SSIM)를 호출할 수 있습니다.
   - 예상 용량 예측 수식: `base_video_bps * 2 ** ((anchor - crf) / crf_divisor)`
   - [알고리즘 고도화 / v4.65q]: H.264 기반의 고정 분모(6.0)를 최신 코덱에 일괄 적용하여 
     AV1 등에서 예상 용량이 실제보다 40% 이상 적게 산출되는 중대 오류 발생. 
     -> 해결책: 코덱별 CRF 곡선 민감도를 반영하는 동적 `crf_divisor` 도입 
        (H.264/HEVC = 6.0, VP9 = 7.5, AV1 = 10.0). 이를 통해 예측 정확도 90% 이상 확보.

2. 하드웨어 가속 최적화 (Hardware Acceleration)
   - CPU(가장 정교), NVIDIA(NVENC), Intel(QSV), AMD(AMF) 지원.
   - 각 GPU 제조사별 특성에 맞는 최적의 Preset 및 Profile 플래그를 자동으로 매핑.

[3. 오류 방지 및 파일 무결성 관리 알고리즘 (Safety & Integrity Logic)]
--------------------------------------------------------------------------------
1. 완벽한 원본 파일명 및 확장자 제어 알고리즘
   - 원본 이름 유지, 정보 접미사(코덱/해상도/CRF 등) 부착 등 다양한 Naming Rule 지원.
   - [오류 해결 / v4.65r]: '기존 파일명 유지' 모드 시 사용자가 지정한 '출력 포맷(MP4 등)'이 
     무시되고 원본 확장자(MKV 등)가 강제되는 오류 발생.
     -> 해결책: 정규식 `r'\(\.(.+?)\)'`을 통해 사용자가 콤보박스에서 선택한 확장자를 
        우선적으로 강제 추출하여 대입하고, 실패 시에만 원본 확장자로 폴백(Fallback)하도록 우선순위 재정립.

2. 설정 파일(app_config.json) 저장 경로 오염 방지
   - [오류 해결 / v4.65s]: AppConfigManager()를 파일명만("app_config.json")으로 호출하여 
     저장 경로가 런타임 CWD(현재 작업 디렉토리) 기준으로 결정되었음.
     FFmpeg 인코딩 작업 중 CWD가 출력 폴더로 바뀌는 경우, app_config.json이 
     사용자의 동영상 출력 폴더에 매번 생성되는 오염 현상 발생.
     -> 해결책: `sys.frozen`(PyInstaller EXE 여부) 판별 후 EXE는 `sys.executable`, 
        스크립트는 `__file__`을 기준으로 `Path.resolve().parent`를 통해 
        앱이 위치한 폴더를 고정 산출하여 항상 그곳에만 config 파일을 저장하도록 수정.

3. 구형 컨테이너(포맷) 충돌 방지 로직
   - [오류 방지]: 3GP, WMV, FLV 등 구형 미디어 컨테이너는 AV1, HEVC 등 최신 코덱을 담지 못해 
     FFmpeg Muxing 에러를 발생시킴.
   - -> 해결책: 원본이 구형 컨테이너이면서 최신 코덱으로 인코딩을 시도할 경우, 
        앱 내부적으로 컨테이너를 강제로 MP4 또는 MKV로 자동 전환하는 안전망(Fallback) 로직 작동.

3. 엄격한 '원본 삭제' 조건부 활성화 알고리즘 (Anti-Data Loss)
   - [오류 방지 / v4.65p]: 원본 덮어쓰기나 의도치 않은 파일 유실을 원천 차단하기 위해 
     '작업 완료 후 원본 삭제' 옵션의 자동 활성화(체크) 조건을 매우 엄격하게 제한함.
   - -> 해결책 (3-Way Check): (1) 저장 위치가 '원본 폴더'이고, (2) 파일명 모드가 '기존 파일명 유지'이며, 
        (3) 대기열의 모든 파일이 "원본 확장자 == 선택한 출력 포맷"일 때만 옵션을 자동 활성화함.
   - 삭제 방식 또한 완전 삭제가 아닌 휴지통(Send2Trash) 이동 메커니즘을 사용하여 2중 보호.

[4. 오디오, 해상도 및 영상 처리 기술 (Media Processing Techniques)]
--------------------------------------------------------------------------------
1. 스마트 필터링 및 미디어 분석 (ffprobe Analyzer)
   - 대기열 추가 시 단순 확장자뿐 아니라 `ffprobe`를 이용해 실제 비디오 스트림 유무 판별.
   - [오류 방지]: 안드로이드 기기에서 생성된 모션 사진(Motion Photo)이나 1초 미만의 
     단순 슬라이드 이미지가 동영상으로 취급되어 인코딩이 멈추는 오류 방지.
     -> `is_jpeg` 판별식과 `duration <= 0.5` 등을 결합한 정밀 필터링 제공.

2. 해상도(비율) 조절 및 회전 알고리즘
   - 해상도 스케일링 시 비율 불일치에 대비한 Letterbox(여백 추가) 및 Crop(화면 채우기) 알고리즘 분기.
   - EXIF 메타데이터 기반 무손실 회전(Fast mode)과 구형 기기 호환을 위한 완전 재인코딩 하드 회전 모드 분리.

3. 자막 (Subtitles) 스트림 매핑
   - 원본 영상에 포함된 자막 스트림(SRT, ASS 등)을 유지(`-c:s copy`), 제거, 
     또는 영상 픽셀 자체에 구워넣는(Burn-in) 기능 지원.

--------------------------------------------------------------------------------
[5. 메타데이터 및 스트리밍 최적화 (Metadata & Network)]
--------------------------------------------------------------------------------
1. 메타데이터 무조건 계승 원칙 (Metadata Preservation)
   - 압축 후에도 생성 일자(Creation Time), 수정 일자, GPS 위치 정보, 카메라 제조사 등 
     Exif/Metadata를 원본과 동일하게 100% 무손실 복사. (가족 사진/동영상 분류 아카이브 목적 최적화)

2. 웹 스트리밍 최적화 (Faststart)
   - MP4 파일 생성 시 `moov atom` 데이터를 파일 헤더(앞부분)로 이동시키는 `-movflags +faststart` 적용.
   - 웹 브라우저나 메신저 업로드 시 영상 전체를 다운로드하지 않아도 즉시 스트리밍 재생이 가능토록 구현.
